# RHD - LifeCore

**Arma 3 Life RP framework | Author: LT. Toad | Version 2.1.1**

RHD - LifeCore is split into two deliberately separate pieces:

```text
RHD---Life-Core-
├─ addons/                     <- MOD SOURCE; compiled into @RHD-LifeCore
│  ├─ rhd_lifecore/
│  └─ rhd_clothing/
├─ core/                       <- MISSION SOURCE
├─ description.ext             <- MISSION SOURCE
├─ initServer.sqf              <- MISSION SOURCE
├─ initPlayerLocal.sqf         <- MISSION SOURCE
├─ assets/                     <- MISSION SOURCE (branding)
└─ .github/workflows/           <- automated build/package jobs
```

The generated server package keeps those parts separate so the mod is installed in the Arma 3 launcher while the mission is copied to `MPMissions`.

## 1. REQUIRED MODS

Only these external Workshop addons are hard dependencies of the RHD addon:

| Addon | Steam Workshop ID | Required |
|---|---:|---|
| CBA_A3 | `450814997` | Yes |
| cTab+ | `2262006564` | Yes |
| Antistasi Ultimate / A3A | — | No; optional integration |
| ACE3 | — | No; optional integration |

RHD declares only CBA_A3 and cTab+ in `requiredAddons[]`. Antistasi Ultimate and ACE3 are detected at runtime and never need to be installed just to load RHD.

## 2. INSTALL THE MOD

Download/build the RHD addon package and place it in your Arma 3 directory as:

```text
Arma 3/
└─ @RHD-LifeCore/
   └─ addons/
      ├─ rhd_rhd_lifecore.pbo
      └─ rhd_rhd_clothing.pbo
```

In the **Arma 3 Launcher** add/enable:

```text
CBA_A3
cTab+
RHD - LifeCore
```

Load any other content mods required by your chosen mission. They do not become RHD hard dependencies.

## 3. CREATE THE MISSION

The mission itself is **not** the mod. Use the mission source in this repository to build an Eden mission.

Required mission-side files:

```text
description.ext
initServer.sqf
initPlayerLocal.sqf
core/
assets/
mission.sqm                 <- generated by Eden; never hand-write it
```

Do not copy PBOs into the mission folder.

### Easiest workflow

1. Open **3DEN** with the map you are building on.
2. Build the mission normally.
3. Copy `description.ext`, `initServer.sqf`, `initPlayerLocal.sqf`, `core/` and `assets/` from this repository into the mission folder.
4. Use 3DEN to place the RHD modules and map markers/objects below.
5. Save the mission from Eden. Eden writes `mission.sqm` for you.

The automated server package described later creates this exact separation for you.

## 4. 3DEN SETUP — REQUIRED

Open **Systems** in Eden and place exactly **one**:

```text
RHD - LifeCore | Life RP Systems
```

Recommended attributes:

| Setting | Default | Purpose |
|---|---|---|
| Economy / Shops | ON | Virtual market + dynamic vehicle/equipment shops |
| Jobs | ON | Civilian, Farmer, Miner, Refiner, Police, EMS |
| Farming / Mining / Refining | ON | RHD virtual resource loop |
| Police / EMS / RP | ON | Tickets, medical and dispatch systems |
| Life RP Persistence | ON | Saves RHD player state server-side |
| Ambient Life | ON | Civilian/incident director |
| RHD Billboard Branding | ON | Applies RHD artwork to supported billboards |
| cTab Player Tablet | ON | RHD tablet hosted through required cTab+ |
| Life District Pressure | ON | RHD civilian crime/heat districts |

### Optional Antistasi module

When Antistasi Ultimate is installed and you want campaign integration, place exactly one:

```text
RHD - LifeCore | Antistasi Ultimate Bridge (Optional)
```

Use the bridge position as the desired campaign start/HQ anchor.

| Setting | Default | Purpose |
|---|---|---|
| Use Antistasi Ultimate when installed | ON | Connect RHD to A3A when A3A is present |
| Create Antistasi HQ Anchors | ON | Creates safe host anchors for the optional bridge |
| Enable Antistasi Terrain Adapter | ON | Installs generic fallback data before A3A startup |

The bridge module may be omitted completely. Omitting it is the supported standalone mode, even when A3A happens to be installed on the server.

## 5. 3DEN MAP MARKERS AND OBJECTS

RHD is terrain-agnostic. Put locations in Eden rather than hard-coding coordinates in SQF.

Use marker names that start with these prefixes:

```text
rhd_shop_<name>            # shop location
rhd_bank_<name>            # bank
rhd_fuel_<name>            # fuel/service
rhd_farm_<resource>_<name> # gathering/farming
rhd_mine_<resource>_<name> # mining
rhd_refine_<resource>_<name> # refining
rhd_zone_<name>            # civilian pressure district
rhd_jail_<name>            # jail
```

Examples:

```text
rhd_shop_city
rhd_bank_city
rhd_fuel_city
rhd_farm_apples_north
rhd_farm_cannabis_south
rhd_mine_iron_quarry
rhd_mine_copper_quarry
rhd_mine_gold_quarry
rhd_mine_diamond_quarry
rhd_mine_oil_oilsands
rhd_refine_iron_factory
rhd_refine_copper_factory
rhd_refine_gold_factory
rhd_refine_oil_refinery
rhd_zone_city
rhd_jail_city
```

The resource names currently configured by default are:

```text
apple
cannabis_plant
coca_leaf
corn_cob
grapes
peaches
iron_ore
copper_ore
gold_ore
diamond
oil_sand
```

### Billboards

Place normal `Land_Billboard_F` objects in Eden. With branding enabled, RHD applies:

```text
assets/branding/RHDLifeCore.jpg
```

Set this object variable on any billboard that must remain untouched:

```sqf
this setVariable ["rhd_billboard_skip", true, true];
```

## 6. MISSION CONFIGURATION — core/fn_init.sqf

This is the **single beginner configuration file** for server-side RHD tuning.

### Identity

```sqf
RHD_VERSION
RHD_DISPLAY_NAME
RHD_AUTHOR
```

### Administrators

`RHD_ADMIN_UIDS` is an array of trusted Steam64 IDs:

```sqf
missionNamespace setVariable ["RHD_ADMIN_UIDS", [
    "76561198000000000",
    "76561198000000001"
], true];
```

Do not use player names; use Steam64 IDs.

### Dynamic shops

```sqf
RHD_SHOP_AUTO_IMPORT
RHD_SHOP_VEHICLE_PRICE_MULTIPLIER
RHD_SHOP_ITEM_PRICE_MULTIPLIER
RHD_SHOP_MAX_VEHICLE_PRICE
RHD_SHOP_MAX_ITEM_PRICE
RHD_SHOP_PRICE_OVERRIDES
```

`RHD_SHOP_AUTO_IMPORT = true` scans the active Arma configuration at runtime. Vehicle shops inspect public land/air/ship classes; equipment shops inspect public weapons, magazines, gear, goggles and backpacks.

Exact overrides use an Arma class name and price:

```sqf
missionNamespace setVariable ["RHD_SHOP_PRICE_OVERRIDES", createHashMapFromArray [
    ["B_MRAP_01_F", 150000],
    ["arifle_MX_F", 5000]
], true];
```

### Jobs

Format:

```text
[job_id, [Display Name, Pay Per Minute]]
```

Default jobs:

```text
civ      Civilian
farmer   Farmer
miner    Miner
refiner  Refinery Worker
police   Police
medic    EMS
```

### Virtual Life RP items

Format:

```text
[item_id, [Display Name, Unit Value, Cost Reference, Category]]
```

These items are RHD virtual inventory and are not Arma magazine/item classnames.

### Refining

Format:

```text
[input_item, [output_item, output_quantity, input_quantity]]
```

Defaults:

```text
iron_ore   -> iron    (2 ore -> 1 iron)
copper_ore -> copper  (2 ore -> 1 copper)
gold_ore   -> gold    (3 ore -> 1 gold)
oil_sand   -> oil     (2 sand -> 1 oil)
```

### Gathering

Format:

```text
[virtual_item, quantity_per_action]
```

### Optional Antistasi integration tuning

```sqf
RHD_A3A_REQUIRED                  // normally false; do not enable as a hard dependency
RHD_A3A_WORLD_BRIDGE_ENABLE
RHD_A3A_CRIME_AGGRESSION_MULTIPLIER
RHD_A3A_CRIME_AGGRESSION_MINUTES
RHD_A3A_ALLOW_RESOURCE_EVENTS
RHD_A3A_ALLOW_BASE_VEHICLE_SPAWN
```

A3A remains the owner of strategic campaign state when the optional bridge is active.

### Standalone district pressure tuning

```sqf
RHD_CONFLICT_ENABLE
RHD_CONFLICT_UPDATE_SECONDS
RHD_CONFLICT_ZONE_RADIUS
RHD_CONFLICT_MAX_HEAT
RHD_CONFLICT_HEAT_DECAY_WITH_POLICE
RHD_CONFLICT_HEAT_GROWTH_NO_POLICE
RHD_CONFLICT_START_SUPPLY
```

These settings affect the RHD-only civilian crime/heat layer around `rhd_zone_*` markers.

### Persistence/startup tuning

```sqf
RHD_PERSISTENCE_SAVE_INTERVAL_SECONDS
RHD_A3A_BRIDGE_WAIT_SECONDS
RHD_STANDALONE_INIT_TIMEOUT_SECONDS
```

The persistence interval controls periodic player saves. The bridge wait controls how long server bootstrap waits for the optional 3DEN Antistasi bridge before selecting standalone startup.

## 7. PLAYER INTERFACE

The RHD tablet is hosted through **cTab+** and exposes:

```text
STATUS
JOBS
MARKET
VEHICLES
EQUIPMENT
BANK
SERVICES
DISTRICTS
CAMPAIGN
```

The player shortcut is the RHD tablet hotkey configured by the mission UI (F6/F7/F8 surfaces are used by the current RHD menus).

ACE3 is optional. When ACE3 is installed, RHD adds ACE contextual actions for the tablet, administration and EMS. Without ACE3, RHD does not call ACE functions.

## 8. ADMIN SETUP

Administration is separate from the player tablet and is UID-gated.

Edit:

```text
core/fn_init.sqf
```

Set:

```sqf
missionNamespace setVariable ["RHD_ADMIN_UIDS", ["YOUR_STEAM64_ID"], true];
```

Then use the RHD admin interface in-game. Do not place a public admin action that bypasses the UID check.

## 9. ANTISTASI ULTIMATE MODE

RHD has two supported modes:

```text
STANDALONE
  RHD Life RP systems run without A3A.

ANTISTASI
  A3A is installed and the optional RHD Antistasi Bridge is placed.
  A3A remains authoritative for strategic campaign state.
```

RHD never copies Antistasi PBOs into the mission and does not make A3A a hard addon dependency.

The optional bridge may provide:

```text
campaign status
strategic pressure hooks
campaign/HQ context
terrain fallback support
```

Terrain-specific A3A `mapInfo` remains the preferred source when supplied by A3A.

## 10. SERVER / LAUNCHER INSTALLATION

### Client launcher

Enable:

```text
CBA_A3
cTab+
RHD - LifeCore
```

Optionally enable:

```text
Antistasi Ultimate
ACE3
other mission content mods
```

### Dedicated server

Place the same modset on the dedicated server. The launcher is for loading the mod; the mission remains a mission file selected/deployed separately.

Recommended layout:

```text
Arma3Server/
├─ @RHD-LifeCore/
│  └─ addons/*.pbo
├─ MPMissions/
│  └─ RHD_LifeCore.<world>.pbo
└─ server.cfg
```

The server must use the same required RHD external addons as the clients.

## 11. READY-TO-DEPLOY PACKAGE

The repository includes an automated packaging workflow that builds the PBOs and produces a server package with this separation:

```text
RHD-LifeCore-ServerPackage/
├─ @RHD-LifeCore/
│  └─ addons/
│     ├─ rhd_rhd_lifecore.pbo
│     └─ rhd_rhd_clothing.pbo
├─ mission-source/
│  ├─ description.ext
│  ├─ initServer.sqf
│  ├─ initPlayerLocal.sqf
│  ├─ core/
│  └─ assets/
└─ README-INSTALL.txt
```

Use the **RHD-LifeCore-ServerPackage** artifact from GitHub Actions after a successful build. Copy the `@RHD-LifeCore` folder to the Arma 3 installation and copy the mission source into an Eden mission folder, then save the mission so Eden generates the final `mission.sqm`.

## 12. BUILD / VALIDATION

This repo uses HEMTT for addon compilation. The automated build performs:

```text
hemtt check
hemtt build
PBO existence checks
compiled-class checks for RHD clothing
source-document leak checks
```

The build workflow is the authoritative test that the addon PBOs compile. A successful CI build does not replace an in-game dedicated-server test of your specific terrain and mission.sqm.

## 13. DO NOT EDIT THESE BY HAND

```text
mission.sqm          <- generated by Eden
addons/*.pbo         <- generated build output
vendor/antistasi-*   <- development/auditing source reference
```

Keep map coordinates and object placement in Eden. Keep prices, jobs, virtual items and tuning in `core/fn_init.sqf`.
